Instructor guide

Everything you need to teach Seaborn with Penguins: who it's for, how to schedule it, what to emphasize in each lesson, where students stumble, and how to assess them.

Course at a glance

Topic Details
Audience Learners comfortable with Python basics and pandas (selecting columns, filtering, groupby). No prior plotting experience needed.
Outcome Learners can choose an appropriate chart for a question, build it in seaborn, finish it with matplotlib, and defend their design choices with established principles (Few, Tufte).
Format 7 lessons of 45-75 minutes. Each has worked examples, design-principle callouts, auto-checked exercises with solutions, and a 4-question quiz.
Dataset Palmer penguins (344 rows, 7 columns), used throughout so cognitive load stays on visualization, not on new data.
Software seaborn 0.13.x, matplotlib ≥ 3.8, pandas ≥ 2.0. Runs in the browser (Pyodide), in Google Colab, or locally.

Learning outcomes

By the end of the course learners can:

  1. Map DataFrame columns to visual channels (x, y, hue, style, size, col, row).
  2. Choose a chart form from the question: distribution, comparison, relationship, composition.
  3. Build histograms, KDEs, ECDFs, count/bar/box/violin/strip/point plots, scatter/regression/line plots, heatmaps and pair plots.
  4. Use figure-level functions for small multiples and plt.subplots + ax= for custom layouts.
  5. Finish charts with matplotlib: labels, titles, annotations, reference lines, tick formatting, and saving.
  6. Critique and improve charts using data-ink, consistent color, highlighting, direct labeling, and honest scales.

Suggested schedules

Format Plan
Seven 75-minute sessions One lesson per session: 10 min recap and quiz review, 30 min live-coding the examples, 30 min exercises, 5 min quiz.
Two half-day workshops Day 1: Lessons 1-4 (break after Lesson 2). Day 2: Lessons 5-7, with the capstone as a 60-minute studio.
Self-paced with check-ins Learners complete one or two lessons a week. Weekly 30-minute office hour on the design principle callouts.
Flipped Learners read and run the lesson before class. Class time goes to the exercises, chart critiques, and the assignments.

Assignment 1 fits after Lesson 3, Assignment 2 after Lesson 5, and Assignment 3 after Lesson 7.

Answers in a public repository

The repository is public so GitHub Pages can serve the site for free. That means the instructor edition and the YAML sources are visible to anyone who looks. For graded use, either keep a private copy of instructor/ (for example in a private fork), or edit the questions and assignments before you use them. Every in-page exercise shows its solution on purpose. Those exercises are for practice, not grading.

Before you teach

  • Test the in-browser Python on the classroom network and devices. The first run downloads about 30 MB from cdn.jsdelivr.net. Locked-down networks or old browsers may block it. Colab and local notebooks are the fallback.
  • Pin versions for a local install: pip install -r requirements.txt (seaborn 0.13.2). Older seaborn versions differ (ci= instead of errorbar=, no linestyle= in pointplot), and those differences are the most common source of “it works on the site but not on my laptop.”
  • Run the tests after any edit: python -m pytest. The build executes every example and checks every exercise solution, so broken content can’t ship.

Lesson-by-lesson notes

Lesson 1 - Your first plot

  • Core idea: seaborn = DataFrame + column names mapped to visual channels. Spend the first 10 minutes on that table. It pays off all course long.
  • Live-code: start with the bare scatter, then add hue, then the ax.set(...) labels. Ask the room what title they’d give before you reveal “Longer flippers, heavier penguins.”
  • The hook: the bill paradox. Show the gray scatter and poll the class: “Do longer bills mean shallower bills?” Then add hue="species". This is the moment most learners remember.
  • Misconceptions: confusing hue= with color= (color takes one color, hue takes a column). In categorical plots (barplot, boxplot, …), passing palette= without hue= raises a FutureWarning in seaborn 0.13. Learners also expect sns.scatterplot to return a figure. It returns an Axes.
  • Exercise tips: 1.1 is fill-in-the-blank. Remind learners the ___ must be replaced with quoted column names. 1.2 is open-ended, so ask two learners to read their titles aloud.

Lesson 2 - Distributions

  • Core idea: look at the shape before you summarize it.
  • Live-code: the three bin widths, then ask “which one is right?” The point is that there’s no single right answer, only an honest one.
  • Discussion: why does common_norm=True make Chinstraps look rare in a KDE? (Because they are rarer. The question is whether you want to compare shapes or counts.)
  • Misconceptions: reading a KDE’s y-axis as a count. Thinking ECDFs are “advanced.” Learners usually find them the easiest to read once shown, so do the “follow the dashed line up” exercise together.
  • Few connection: common baselines. The stacked histogram is a good “spot the problem” moment.

Lesson 3 - Comparing categories

  • Core idea: bars for amounts from zero, points when zero is meaningless, and box/strip to show the distribution.
  • Live-code: the default barplot, then ask “what are the black lines?” Most learners guess min/max or standard deviation. Explain the 95% bootstrap CI and the errorbar= options table.
  • The truncated-axis chart makes a good 2-minute critique. Ask learners to estimate “how many times heavier are Gentoos?” from it, then reveal the real ratio (about 1.4).
  • Misconceptions: sorting the DataFrame rows to sort the bars (use order=). Using palette= without hue=. Assuming the box plot’s whiskers are the min/max (they reach 1.5 × IQR).
  • Few connection: sort by value, use horizontal bars for long labels, and no pies.

Lesson 4 - Relationships

  • Core idea: a fitted line is a model. A line chart asserts that x is ordered.
  • Live-code: the paradox overlay (regplot + groupby loop). It reinforces Lesson 1 and introduces drawing several layers on one ax.
  • Heatmap checklist: diverging cmap, center=0, vmin=-1, vmax=1, annotate, and mask the mirror half. Have learners say why each argument matters.
  • Misconceptions: reading the regression band as a prediction interval for individual penguins. Using lineplot across islands or species.
  • Pacing: pairplot is slow in the browser (a few seconds). Show it once rather than asking everyone to re-run it.

Lesson 5 - Small multiples

  • Core idea: axes-level vs figure-level. Put the four-row table on the board and refer back to it.
  • Live-code: turn one crowded chart into a relplot(col="island"). Then ask what changed and what stayed the same (the shared axes).
  • Misconceptions: passing ax= or figsize= to figure-level functions (use height/aspect). Calling plt.title() on a grid (use g.figure.suptitle). Using g.fig, the older spelling of g.figure.
  • Few connection: small multiples and shared scales. Discuss when unsharing y is defensible.

Lesson 6 - Polish with matplotlib

  • Core idea: seaborn makes the chart, and matplotlib makes the point.
  • The makeover is the centerpiece. Show the “before” chart and ask learners to list problems for 3 minutes before you show the code for “after.” Then map each fix to the Few checklist table.
  • Palettes: connect the categorical/sequential/diverging jobs back to the heatmap (Lesson 4) and species colors (Lesson 1).
  • Misconceptions: expecting sns.set_theme() to change an already-drawn chart. Forgetting ax= and drawing everything on the last subplot. Mixing up ax.set_title and fig.suptitle.

Lesson 7 - Capstone

  • Core idea: questions → forms → layout → polish → review.
  • Run it as a studio: learners plan the four panels on paper first (5 min), build them (35 min), then do peer review against the pre-flight checklist (15 min).
  • Common struggles: legends in every panel (show fig.legend with loc="outside lower center"), crowded titles (layout="constrained"), inconsistent species order (hue_order).

Assessment

Formative: in-page quizzes and exercises

Each lesson ends with a 4-question quiz. The score counts first attempts, and a lesson is marked complete in the sidebar once every question has been answered correctly. Exercises are auto-checked in the browser and give specific hints. Solutions are available on purpose, so encourage learners to try before they peek. The correct answers are spread evenly across A-D (7 of each across the 28 quiz questions).

Summative: the 25-question exam

Lesson Questions
1 - First plot Q1-Q4
2 - Distributions Q5-Q8
3 - Categories Q9-Q13
4 - Relationships Q14-Q17
5 - Small multiples Q18-Q21
6 - Polish Q22-Q24
7 - Capstone Q25

Answers are balanced (A = 6, B = 6, C = 7, D = 6). The correct option is the longest option in only 7 of 25 questions, close to the chance rate, so test-wise guessing doesn’t help. Allow about 35 minutes. A suggested pass mark is 18/25 (72%).

Assignments

# Title After Time Focus
1 Island Census Lesson 3 ~1 h Correct chart types, sorting, consistent color, labels
2 Are males really bigger? Lesson 5 ~2 h Small multiples, point plots, heatmap layout, evidence-based writing
3 Field Report 2.0 Lesson 7 3-4 h Derived variable, multi-panel design, makeover, design rationale

Each has a 100-point rubric. Weight design and communication as heavily as code. The model solutions in the instructor edition were executed to produce the figures shown. Grading tips:

  • Accept any reasonable bin width, threshold or title that the learner justifies. The rubric rewards deliberate choices, not matching the model answer.
  • Deduct for chart crimes even when the code is correct: truncated bars, rainbow palettes, unlabeled units, legends covering data.
  • For Assignment 3, the design rationale is where you’ll see whether the principles stuck. Look for principles applied to specific changes, not a list of buzzwords.

Teaching the design thread

The design principle callouts (marked “Design principle”) carry the course’s second curriculum. Reinforce them:

  • Start every critique with “what question does this answer?” If nobody can say, the form doesn’t matter yet.
  • Name the principle when you fix something. For example: “I’m removing this legend: direct labeling.”
  • Keep one color dictionary on screen. PENGUIN_COLORS is a small but powerful habit. Learners who adopt it produce noticeably more coherent multi-chart work.
  • Use the before/after pair from Lesson 6 as a reference throughout. It shows six principles in one chart.

Accessibility and inclusion

  • The species palette was checked for distinguishability under protanopia, deuteranopia and tritanopia (minimum pairwise ΔE of about 16 in OKLab). Still, never rely on color alone: shape, position and direct labels carry identity too.
  • Every figure on the site has descriptive alt text, and the in-browser editors are keyboard-accessible (Ctrl/Cmd + Enter runs, Esc then Tab leaves the editor).
  • Ask learners to write alt text for their assignment charts. It’s an excellent test of whether they know what the chart says.

Troubleshooting

Symptom Likely cause and fix
“Python: failed to load” on the site Network blocks cdn.jsdelivr.net, or the browser is very old. Use the Colab link or a local notebook.
FutureWarning: Passing palette without assigning hue seaborn 0.13 wants hue= whenever palette= is used. Add hue="species" (and legend=False if it’s redundant).
TypeError: ... got an unexpected keyword argument 'errorbar' seaborn older than 0.12. Upgrade: pip install -U "seaborn>=0.13".
Chart doesn’t appear when running a .py script Add plt.show() at the end (notebooks display automatically).
Everything drawn on one subplot ax= was forgotten on later calls.
Labels cut off in saved PNG Use bbox_inches="tight" or layout="constrained".
Facet titles read “species = Gentoo” g.set_titles("{col_name}").

Customizing the course

  • Edit a lesson: change content/NN-*.md, run python tools/build_site.py, and review the page locally (python -m http.server -d docs).
  • Add an exercise: add an exercise, solution and check fence with matching ids. The build fails if the solution doesn’t pass its check, or if the untouched starter already does.
  • Edit the exam or assignments: change the YAML in instructor/ and run python tools/build_materials.py. pytest checks the answer balance.
  • Swap the dataset: possible, but every example, check and quiz explanation is written for penguins. Plan on a full rewrite of the content files rather than a find-and-replace.
