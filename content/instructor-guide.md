# Instructor guide

<p class="lede">Everything you need to teach <em>Seaborn with Penguins</em>: who it's for, how to schedule it, what to emphasize in each lesson, where students stumble, and how to assess them.</p>

## Course at a glance

| Topic | Details |
|---|---|
| **Audience** | Learners comfortable with Python basics and pandas (selecting columns, filtering, `groupby`). No prior plotting experience needed. |
| **Outcome** | Learners can choose an appropriate chart for a question, build it in seaborn, finish it with matplotlib, and defend their design choices with established principles (Few, Tufte). |
| **Format** | 7 lessons of 45-75 minutes. Each has worked examples, design-principle callouts, auto-checked exercises with solutions, and a 4-question quiz. |
| **Dataset** | Palmer penguins (344 rows, 7 columns), used throughout so cognitive load stays on visualization, not on new data. |
| **Software** | seaborn 0.13.x, matplotlib ≥ 3.8, pandas ≥ 2.0. Runs in the browser (Pyodide), in Google Colab, or locally. |

### Learning outcomes

By the end of the course learners can:

1. Map DataFrame columns to visual channels (`x`, `y`, `hue`, `style`, `size`, `col`, `row`).
2. Choose a chart form from the question: distribution, comparison or relationship (and recognize that most "composition" questions are better answered with sorted bars than with a pie).
3. Build histograms, KDEs, ECDFs, count/bar/box/violin/strip/point plots, scatter/regression/line plots, heatmaps and pair plots.
4. Use figure-level functions for small multiples and `plt.subplots` + `ax=` for custom layouts.
5. Finish charts with matplotlib: labels, titles, annotations, reference lines, tick formatting, and saving.
6. Critique and improve charts using data-ink, consistent color, highlighting, direct labeling, and honest scales.

For mastery-based teaching, these six outcomes are split into fourteen objectives that can be checked one at a time. See [Mastery objectives](#mastery-objectives).

## Before you teach

- **Test the in-browser Python** on the classroom network and devices. The first run downloads about 30 MB from `cdn.jsdelivr.net`. Locked-down networks or old browsers may block it. Colab and local notebooks are the fallback.
- **Pin versions** for a local install: `pip install -r requirements.txt` (seaborn 0.13.2). Older seaborn versions differ (`ci=` instead of `errorbar=`, no `linestyle=` in `pointplot`), and those differences are the most common source of "it works on the site but not on my laptop."
- **Run the tests** after any edit: `python -m pytest`. The build executes every example and checks every exercise solution, so broken content can't ship.

## Lesson-by-lesson notes

### Lesson 1 - Your first plot

- **Core idea:** seaborn = DataFrame + column names mapped to visual channels. Spend the first 10 minutes on that table. It pays off all course long.
- **Live-code:** start with the bare scatter, then add `hue`, then the `ax.set(...)` labels and the legend title (`ax.get_legend().set_title("Species")`: seaborn titles a legend with the raw column name). Ask the room what title they'd give before you reveal "Longer flippers, heavier penguins."
- **The hook:** the bill paradox. Show the gray scatter and poll the class: "Do longer bills mean shallower bills?" Then add `hue="species"`. This is the moment most learners remember.
- **Misconceptions:** confusing `hue=` with `color=` (`color` takes one color, `hue` takes a column). In categorical plots (`barplot`, `boxplot`, ...), passing `palette=` without `hue=` raises a FutureWarning in seaborn 0.13. Learners also expect `sns.scatterplot` to return a figure. It returns an `Axes`. Finally, seaborn orders hue and style levels by first appearance in the data (so `sex` comes out Male, then Female); `hue_order=` and `style_order=` take control of that.
- **Exercise tips:** 1.1 is fill-in-the-blank. Remind learners the `___` must be replaced with *quoted* column names. 1.2 is open-ended, so ask two learners to read their titles aloud.

### Lesson 2 - Distributions

- **Core idea:** look at the shape before you summarize it.
- **Live-code:** the three bin widths, then ask "which one is right?" The point is that there's no single right answer, only an honest one.
- **Discussion:** why does `common_norm=True` make Chinstraps look rare in a KDE? (Because they *are* rarer. The question is whether you want to compare shapes or counts.)
- **Misconceptions:** reading a KDE's y-axis as a count. Expecting `binwidth=` to be exact: seaborn fits a whole number of bins to the data's range unless `binrange=` is given, so `binwidth=3` on flipper length draws 2.95 mm bins. Thinking ECDFs are "advanced." Learners usually find them the easiest to *read* once shown, so do the "follow the dashed line up" exercise together.
- **Few connection:** common baselines. The stacked histogram is a good "spot the problem" moment.

### Lesson 3 - Comparing categories

- **Core idea:** bars for amounts from zero, points when zero is meaningless, and box/strip to show the distribution.
- **Live-code:** the default `barplot`, then ask "what are the black lines?" Most learners guess min/max or standard deviation. Explain the 95% bootstrap CI and the `errorbar=` options table.
- **The truncated-axis chart** makes a good 2-minute critique. Ask learners to estimate "how many times heavier are Gentoos?" from it, then reveal the real ratio (about 1.4).
- **Misconceptions:** sorting the DataFrame rows to sort the bars (use `order=`). Using `palette=` without `hue=`. Assuming the box plot's whiskers are the min/max (they extend to the furthest point within 1.5 × IQR of the box, and anything beyond is drawn as an outlier).
- **If you delete `legend=False` in front of the class,** nothing changes in this lesson's box, violin and strip plots or in exercise 3.2: seaborn 0.13 leaves the legend out by itself when the `hue` column is the one on the categorical axis. The argument still says what you mean, and it is needed as soon as `hue` is another column, or has missing values, as with `sex` in Lesson 5's `catplot`.
- **Few connection:** sort by value, use horizontal bars for long labels, and no pies.

### Lesson 4 - Relationships

- **Core idea:** a fitted line is a model. A line chart asserts that x is ordered.
- **Live-code:** the paradox overlay (`regplot` + `groupby` loop). It reinforces Lesson 1 and introduces drawing several layers on one `ax`.
- **Heatmap checklist:** diverging cmap, `center=0`, `vmin=-1, vmax=1`, annotate, and mask the mirror half. Have learners say why each argument matters.
- **Misconceptions:** reading the regression band as a prediction interval for individual penguins. Using `lineplot` across islands or species.
- **Pacing:** `pairplot` is slow in the browser (a few seconds). Show it once rather than asking everyone to re-run it.

### Lesson 5 - Small multiples

- **Core idea:** axes-level vs figure-level. Put the four-row table on the board and refer back to it.
- **Live-code:** turn one crowded chart into a `relplot(col="island")`. Then ask what changed and what stayed the same (the shared axes). Add `col_order=` last, and ask why Torgersen came first without it (order of first appearance, the same rule as hue and style levels in Lesson 1).
- **Misconceptions:** passing `ax=` or `figsize=` to figure-level functions (use `height`/`aspect`). Calling `plt.title()` on a grid (use `g.figure.suptitle`). Using `g.fig`, the older spelling of `g.figure`.
- **Few connection:** small multiples and shared scales. Discuss when unsharing y is defensible.

### Lesson 6 - Polish with matplotlib

- **Core idea:** seaborn makes the chart, and matplotlib makes the point.
- **The makeover** is the centerpiece. Show the "before" chart and ask learners to list problems for 3 minutes before you show the code for "after." Then map each fix to the Few checklist table.
- **Palettes:** connect the categorical/sequential/diverging jobs back to the heatmap (Lesson 4) and species colors (Lesson 1).
- **Misconceptions:** expecting `sns.set_theme()` to change an already-drawn chart. Forgetting `ax=` and drawing everything on the last subplot. Mixing up `ax.set_title` and `fig.suptitle`.
- **Global state:** the "before" chart switches style inside `with sns.axes_style("darkgrid"):`, so nothing leaks into later cells. Exercise 6.1 deliberately leaves a bare `sns.set_theme(style="darkgrid")` in the starter, and its checker insists on the reset, because "someone changed the theme three cells ago" is a real-life bug worth meeting once.
- **Exercise tips:** 6.3 asks for the two polish moves that the makeover shows and 6.1 and 6.2 do not practice: `ax.annotate` with an arrow, and a tick formatter. It points at the lightest penguin, where the makeover points at the heaviest, so the lesson's lines cannot be pasted in unchanged. `ax.text` does not pass: it has no arrow. Allow about 10 minutes on top of the lesson.

### Lesson 7 - Capstone

- **Core idea:** questions → forms → layout → polish → review.
- **Run it as a studio:** learners plan the four panels on paper first (5 min), build them (35 min), then do peer review against the pre-flight checklist (15 min).
- **Common struggles:** legends in every panel (show `fig.legend` with `loc="outside lower center"`), crowded titles (`layout="constrained"`), inconsistent species order (`hue_order`).

## Assessment

### Formative: in-page quizzes and exercises

Each lesson ends with a 4-question quiz. The score counts first attempts, and a lesson is marked complete in the sidebar once every question has been answered correctly. Exercises are auto-checked in the browser and give specific hints. Solutions are available on purpose, so encourage learners to try before they peek. The correct answers are spread evenly across A-D (7 of each across the 28 quiz questions).

### Summative: the 25-question exam

| Lesson | Questions |
|---|---|
| 1 - First plot | Q1-Q4 |
| 2 - Distributions | Q5-Q8 |
| 3 - Categories | Q9-Q12 |
| 4 - Relationships | Q13-Q16 |
| 5 - Small multiples | Q17-Q20 |
| 6 - Polish | Q21-Q23 |
| 7 - Capstone | Q24-Q25 |

Answers are balanced (A = 6, B = 6, C = 7, D = 6). The correct option is the longest one in only 1 of 25 questions and the shortest in 3, so option length is no guide, and `pytest` fails if an edit upsets the balance. Allow about 35 minutes. A suggested pass mark is 18/25 (72%). For mastery-based use, see [Deciding mastery](#deciding-mastery).

### Assignments

| # | Title | After | Time | Focus |
|---|---|---|---|---|
| 1 | Island Census | Lesson 3 | ~1 h | Correct chart types, sorting, consistent color, labels |
| 2 | Are males really bigger? | Lesson 5 | ~2 h | Small multiples, point plots, heatmap layout, evidence-based writing |

Each has a 100-point rubric, and both editions of the pack state the three-level scale the rubrics assume (full credit, about half for a present-but-flawed element, zero for missing or wrong). Weight design and communication as heavily as code. The model solutions in the instructor edition were executed to produce the figures shown. **Grading tips:**

- Accept any reasonable bin width, threshold or title that the learner *justifies*. The rubric rewards deliberate choices, not matching the model answer.
- Deduct for chart crimes even when the code is correct: truncated bars, rainbow palettes, unlabeled units, legends covering data.
- For Assignment 3, the design rationale is where you'll see whether the principles stuck. Look for principles applied to *specific* changes, not a list of buzzwords.

### Deciding mastery

1. An objective is mastered when (1) every exercise that checks it on the pages that teach it passes its automatic check, shown to the instructor or handed in as the lesson's notebook with its outputs, and (2) the learner scores 80% or better on a mastery check for that objective. The Objectives sheet names those exercises under 'Practice today'. An exercise on another page that also checks the objective is further practice, and mastery does not wait for it.
2. A mastery check is five questions the learner has not seen with their answers, or a rubric-scored task at full credit on the rubric rows mapped to the objective. On the assessment pack's three-level scale, 'about half' means not yet.
3. Not yet? The learner reworks the sections that teach the objective (Page detail sheet, filter on the objective), redoes its exercises from Reset, and takes a different check. There is no penalty for a second attempt.
4. Mastered early? The learner moves to the next objective whose prerequisites are met, or starts the next assignment.
5. With today's materials: no mastery check is written yet. Until one is, a learner moves on from an objective when its exercises under rule 1 pass, and the rubric rows of the next assignment confirm the objective or send the learner back to it. The exam has at most four questions per objective and its answer key is public, so use its questions to find what to rework, not to decide mastery.

The pass mark of 18/25 suggested under Assessment is for a single sitting of the exam. It has no part in this rule.

### Assumptions

The objectives rest on seven assumptions. Each is yours to change in `instructor/mastery_objectives.yaml`.

- The larger course has three sections: static visualization (this site, fourteen objectives), interactive charts (twelve) and dashboards (twelve). This site is section 1 in full.
- Learners arrive with Python basics and pandas, the prerequisite stated on the Start here page. Those skills are not objectives here, which is why one rubric row (Assignment 2, 'Code quality') maps to none.
- The mastery standard is 80% on a check of five unseen questions, which is four of the five, or full credit on the mapped rubric rows, with a second attempt on a different check.
- Section 2 uses Plotly. Its objectives are worded so that another library would change the 'Key tools' column, not the objective, except I04 and I07, whose criteria name Plotly's own functions. Plotly links two views only inside a scatter matrix or through a notebook widget, so linking two separate charts (I08) is finished in section 3 (D07). Altair, the alternative that was weighed, links them in a few lines. Section 3 uses Streamlit and is written in its terms (the rerun, session state, caching), so the alternative, Dash, would mean rewriting D02 to D09 and D11. The names in 'Key tools' were checked against the documentation of Plotly 7.1 and Streamlit 1.67.
- An exercise counts as evidence for an objective only when its automatic check tests that objective. S01 is counted in Lesson 1's two exercises alone: later checks also look at which columns are plotted, but to recognize the chart, not to test the mapping. Every quiz question and every exam question is mapped to exactly one objective. A rubric row is mapped to the objectives its 'full credit' text describes.
- Status: Covered means the pages teach the objective, at least one checked exercise practices it, and at least one exam question or rubric row assesses it. Partial means it is taught but practice or assessment is missing. Planned means no page teaches it yet.
- The lesson minutes are estimates (see the Timing sheet). Section 1 splits each existing lesson's 60-minute midpoint across its objectives, and counts what was added to a lesson later on top of it, in a block of its own. Sections 2 and 3 are planning figures to revise after a pilot.

## Teaching the design thread

The design principle callouts (marked "Design principle") carry the course's second curriculum. Reinforce them:

- **Start every critique with "what question does this answer?"** If nobody can say, the form doesn't matter yet.
- **Name the principle when you fix something.** For example: "I'm removing this legend: direct labeling."
- **Keep the two color dictionaries on screen.** `PENGUIN_COLORS` for species and `SEX_COLORS` (two grays) for sex are a small but powerful habit. Learners who adopt them produce noticeably more coherent multi-chart work, and the grays make the point that a second variable shouldn't borrow the first one's colors.
- **Use the before/after pair** from Lesson 6 as a reference throughout. It shows six principles in one chart.

## Accessibility and inclusion

- The species palette was checked for distinguishability under protanopia, deuteranopia and tritanopia (minimum pairwise ΔE of about 16 in OKLab). Still, never rely on color alone: shape, position and direct labels carry identity too.
- The light gray in `SEX_COLORS` keeps at least 3:1 contrast against a white background, and every chart that uses it also varies the marker shape or names the sex on an axis.
- Every figure on the site has descriptive alt text, each quiz question is a labeled group for screen readers, and the in-browser editors are keyboard-accessible (Ctrl/Cmd + Enter runs, Esc then Tab leaves the editor).
- Ask learners to write alt text for their assignment charts. It's an excellent test of whether they know what the chart says.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| "Python: failed to load" on the site | Network blocks `cdn.jsdelivr.net`, or the browser is very old. Use the Colab link or a local notebook. |
| `FutureWarning: Passing palette without assigning hue` | seaborn 0.13 wants `hue=` whenever `palette=` is used. Add `hue="species"` (and `legend=False` if it's redundant). |
| `TypeError: ... got an unexpected keyword argument 'errorbar'` | seaborn older than 0.12. Upgrade: `pip install -U "seaborn>=0.13"`. |
| Chart doesn't appear when running a `.py` script | Add `plt.show()` at the end (notebooks display automatically). |
| Everything drawn on one subplot | `ax=` was forgotten on later calls. |
| Labels cut off in saved PNG | Use `bbox_inches="tight"` or `layout="constrained"`. |
| Facet titles read "species = Gentoo" | `g.set_titles("{col_name}")`. |

## Customizing the course

- **Edit a lesson:** change `content/NN-*.md`, run `python tools/build_site.py`, and review the page locally (`python -m http.server -d docs`).
- **Add an exercise:** add an `exercise`, `solution` and `check` fence with matching ids. The build fails if the solution doesn't pass its check, or if the untouched starter already does.
- **Edit the exam or assignments:** change the YAML in `instructor/` and run `python tools/build_materials.py`. `pytest` checks the answer balance.
- **Edit the objectives or their map:** change `instructor/mastery_objectives.yaml` and run `python tools/build_materials.py`. The build and `pytest` name anything the map points at that no longer exists, and anything new that it leaves out.
- **Swap the dataset:** possible, but every example, check and quiz explanation is written for penguins. Plan on a full rewrite of the content files rather than a find-and-replace.
